03 / Proposed Creative Project Plan

Synthetic Log Lab

The final creative application would follow account → core task → saved result → private dashboard → account maintenance. This research website is a planning artifact. It does not replace that required journey or establish that it works.

  1. As a learner, I can register, sign in, and sign out. Check: invalid credentials fail clearly; a signed-out visitor cannot open saved results.
  2. As a learner, I can inspect a synthetic login scenario and submit an explanation. Check: counts match the fixture; an unsupported attack claim is distinguished from an observed failure pattern.
  3. As a learner, I can save and revisit my result on a private dashboard. Check: refresh retains the result; account B cannot read, change, or delete account A’s result, including by direct URL.
  4. As a learner, I can maintain my account. Check: implement and verify credential recovery, password change, and account deletion with documented ownership checks; verify access is revoked after deletion.

Boundary: only supplied synthetic fixtures; no real log ingestion, threat detection service, automatic remediation, or diagnosis of real users. A failure count is an observation, not proof of intrusion.

First implement a pure Python function that counts failed events by synthetic user. Validate that the top-level input is a list and each event has a string user and a recognized outcome. Reject malformed data with a clear error.

[
  {"user": "learner-a", "outcome": "failure"},
  {"user": "learner-a", "outcome": "failure"},
  {"user": "learner-b", "outcome": "success"}
]

Expected: learner-a has 2 failures; learner-b has 0. Empty input returns no users. A missing outcome or unknown outcome returns a validation error. A username containing instruction-like text is handled only as data.

Observed: no counter, model benchmark, backend, account flow, or persistence experiment has been run. Next, write these cases independently, implement the counter, execute the tests, and link the actual output. Then ask a partner to explain what the result supports and what it cannot establish.
